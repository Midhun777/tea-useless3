AFTER THE MAIN BUILD
MAKING THE CHAI MORE FUN

After getting the main bubble-detection idea working, we didn't stop there. We started thinking about how to make the project feel less like a normal computer-vision demo and more like something people would actually enjoy using.

💻 The Chai Code Terminal

One of the fun features we designed was a code terminal for the chai. Instead of just looking at the bubble-detection result, the user could interact with the chai through a terminal-style interface and type code or commands to influence what happens.

"Okay, we detected the bubbles. Now let's give the chai a terminal."

It gave the project a little personality — like the chai wasn't just sitting there waiting to be analyzed. 😭

🫧 Tea Glass Popper

Then came another slightly ridiculous but fun idea: the Tea Glass Popper. Instead of only detecting bubbles, we made it possible to interact with the bubbles and pop them inside the tea glass.

detect bubbles → count bubbles → actually POP bubbles

"We could've just counted the bubbles… but apparently popping them was necessary."

🚀 Putting It Online

Once we had the webapp together, we hosted it using Vercel so that the project could actually be accessed as a web application rather than only running locally.

It wasn't just: "Look, it works on our laptop." It became: "Here. Open the webapp and try it."

😬 Then the Model Started Acting Up

But there was a problem. The performance of our bubble-detection model started degrading. The detection wasn't staying as reliable as we wanted.

"Hosted successfully. Model performance: …why are you doing this to us?"

🔄 Back to Experimenting

Instead of just accepting the degrading performance, we're now trying to move the bubble-detection part into another software/approach to see if we can get better and more reliable results.

"Still building."
